# Russian Editor

Публичный самостоятельный скилл для ясного русского текста. Он помогает редактировать рабочие сообщения, заметки и объяснения, сохраняя факты, состояние работы и интонацию автора. Автор проекта: Яков Вебер.

Название скилла: `russian-editor`. Лицензия: MIT.

Предусмотрены установка в Codex, Claude Code и OpenCode и плагинная упаковка для Codex и Claude Code. Редакторские инструкции хранятся в одной папке `skills/russian-editor/`. Текущая версия пакета: **1.1.0**.

## Возможности

- Редактура предоставленного текста.
- Аудит с конкретными замечаниями без переписывания.
- Правка только выбранной проблемы.
- Черновик сообщения по предоставленным фактам и тезисам.
- Черновик заметки или объяснения с понятным ходом мысли и границами вывода.
- Разбор приёмов письма на примере автора и совместная работа по шагам.

Скилл не определяет, кто написал текст, не обещает прохождение детекторов и не выдаёт редактуру за проверку фактов. У него нет обязательного сканера, баллов, установки зависимостей или сетевых вызовов.

В основе редакторские решения: сохранить полезную фразу; убрать мешающую оболочку; проверить, не изменилось ли утверждение. Содержательное противопоставление, термин и нужное тире допустимы. Авторскую манеру нельзя создавать выдуманными историями, эмоциями или намеренными ошибками.

Скилл подходит разным авторам и не требует личной базы знаний, образцов или заранее выбранного голоса. Подачу определяют задача и текст пользователя. Если пользователь предоставил профиль, он действует в этой задаче; официальный текст сохраняет свой регистр, короткое сообщение может остаться одной строкой.

## Использование

```text
$russian-editor Отредактируй сообщение. Сохрани сроки и прямой тон:
[текст]
```

```text
$russian-editor Проверь текст, не переписывай. Покажи конкретные проблемы:
[текст]
```

```text
$russian-editor Убери только повторения:
[текст]
```

```text
$russian-editor Напиши сообщение по этим тезисам:
[факты и желаемое действие адресата]
```

```text
$russian-editor Помоги написать объяснение по шагам. Пока разбираем только начало:
[материал]
```

```text
$russian-editor Объясни по пунктам, как устроен этот текст и зачем каждый переход:
[авторский пример]
```

## Установка

### Как скилл

Скопируйте **папку целиком**, включая `references/` и лицензию, в каталог выбранного агента:

| Агент | В проекте | Для всех проектов |
| --- | --- | --- |
| Codex | `.agents/skills/russian-editor/` | `~/.agents/skills/russian-editor/` |
| Claude Code | `.claude/skills/russian-editor/` | `~/.claude/skills/russian-editor/` |
| OpenCode | `.opencode/skills/russian-editor/` | `~/.config/opencode/skills/russian-editor/` |

Пример для проекта Codex, выполняемый из корня скачанного репозитория:

```sh
mkdir -p /path/to/project/.agents/skills
cp -R skills/russian-editor /path/to/project/.agents/skills/
```

Путь `/path/to/project` замените путём своего проекта; для других агентов замените каталог по таблице. Если папка уже существует, сначала сравните версии и сохраните собственные изменения. Установка состоит в копировании Markdown и YAML; код пакета не выполняется.

OpenCode также обнаруживает `.agents/skills` и `.claude/skills`: если скилл уже установлен в совместимом каталоге, вторую копию создавать не требуется. После установки начните новую сессию агента. Каталоги проверены по документации [Codex](https://learn.chatgpt.com/docs/build-skills), [Claude Code](https://code.claude.com/docs/en/skills) и [OpenCode](https://opencode.ai/docs/skills/).

В Codex явно вызовите `$russian-editor`, в Claude Code с обычной установкой `/russian-editor`. В OpenCode попросите загрузить скилл `russian-editor` и выполните текстовую задачу; он использует встроенный инструмент `skill`.

### Как плагин

Плагин даёт пакету имя, версию и установку через каталог с обновлениями. В этом пакете он содержит тот же скилл; дополнительных редакторских возможностей или подключений к сервисам не добавляет. Установка скилла вручную остаётся самостоятельным способом использования. Не устанавливайте оба способа одновременно без необходимости.

В корне находится переносимый `plugin.json` стандарта Agent Plugins. `.codex-plugin/plugin.json` задаёт совместимость и представление для Codex, `.claude-plugin/plugin.json` содержит метаданные Claude Code. Обе упаковки используют общую папку `skills/`. Форматы основаны на документации [OpenAI](https://developers.openai.com/plugins/build/plugins) и [Claude Code](https://code.claude.com/docs/en/plugins-reference).

Для **Codex** добавьте локальный каталог скачанного репозитория:

```sh
codex plugin marketplace add /absolute/path/to/russian-editor-skill
codex plugin list --marketplace russian-editor-marketplace
```

Затем выберите источник `Russian Editor` в каталоге плагинов поддерживаемого приложения Codex/ChatGPT и установите `russian-editor`. Доступность установки зависит от клиента и его версии; обычная установка скилла выше остаётся доступной. Команды добавления каталога сами по себе не подтверждают установку плагина.

Для **Claude Code** выполните в его сессии:

```text
/plugin marketplace add /absolute/path/to/russian-editor-skill
/plugin install russian-editor@russian-editor-marketplace
```

После установки вызовите `/russian-editor:russian-editor`. Для проверки локальных изменений без регистрации каталога можно запустить `claude --plugin-dir /absolute/path/to/russian-editor-skill`.

В **OpenCode** используется установка скилла по таблице. Его [плагины](https://opencode.ai/docs/plugins/) являются JavaScript/TypeScript-модулями с обработчиками событий. Этот редактор не требует такого модуля, поэтому пакет не объявляет совместимость с форматом плагинов OpenCode.

Для установки из GitHub вместо локального пути используйте репозиторий:

```text
Codex: codex plugin marketplace add SingeltonAttero/russian-editor-skill
Claude Code: /plugin marketplace add SingeltonAttero/russian-editor-skill
```

Далее применяется тот же порядок установки. Каталоги в репозитории предназначены для распространения и локальной проверки; наличие этих файлов не означает включение в официальные каталоги OpenAI или Anthropic.

Подробные правила находятся в [SKILL.md](skills/russian-editor/SKILL.md), разборы решений в [examples.md](skills/russian-editor/references/examples.md). Для содержательной разработки и обучения используется [authoring.md](skills/russian-editor/references/authoring.md); обычная вычитка не требует его загрузки.

## Проверка качества

В [eval/cases.json](eval/cases.json) есть 25 сценариев с условиями приёмки. Это ручной набор для проверки на выбранной модели, а не автоматический детектор или оценка человеческого авторства.

Процедура и границы проверки описаны в [eval/README.md](eval/README.md). [Первичная самопроверка](eval/results.md) относится к версии 1.0.0; [самопроверка изменений 1.1.0](eval/results-1.1.md) содержит ответы на девять новых сценариев и границы проверки прежних. Проход этих сценариев не гарантирует сохранение смысла на любом тексте.

Проверка манифестов, обнаружения в каталоге Codex и переносимости файлов описана в [eval/package-checks.md](eval/package-checks.md). Она не подтверждает качество ответов разных моделей или установку в официальном каталоге.

## Происхождение

Для сравнения изучен [ilyautov/humanizer-ru](https://github.com/ilyautov/humanizer-ru) и его инструкции редактуры, аудита и сверки, доступные 7 октября 2026 года. Этот проект не является форком и не содержит исходный каталог паттернов, сканер, тексты примеров или код того проекта. Инструкции и демонстрационные материалы написаны отдельно.

Базовые решения: небольшая правка, простой русский, точные рабочие статусы, авторские термины и отсутствие вводных фраз перед готовым сообщением. Публичные примеры вымышленные; личные адреса и внутренние рабочие переписки в пакет не включены.

Версия 1.1.0 подготовлена 7 октября 2026 года по редакционным наработкам из базы знаний автора. Использованы способы соавторства, построения рассуждения, редакторской проверки и работы с образцами: достаточный материал сразу становится черновиком; существенный выбор обсуждается с рекомендуемым вариантом; объяснение раскрывает механизм и условия; обучение показывает приём на конкретном фрагменте.

Исходные заметки остаются в базе знаний. Пакет содержит самостоятельную адаптацию и вымышленные примеры, работает без доступа к базе. В него не перенесены личные сведения, тексты постов, настройки публикации и обязательный стиль отдельного канала. Явный профиль автора применяется только в соответствующей задаче.
