# Russian Editor

Самостоятельный скилл Якова Вебера для ясного русского текста. Он помогает редактировать рабочие сообщения, заметки и объяснения, сохраняя факты, состояние работы и интонацию автора.

Название скилла: `russian-editor`. Лицензия: MIT.

## Возможности

- Редактура предоставленного текста.
- Аудит с конкретными замечаниями без переписывания.
- Правка только выбранной проблемы.
- Черновик сообщения по предоставленным фактам и тезисам.

Скилл не определяет, кто написал текст, не обещает прохождение детекторов и не выдаёт редактуру за проверку фактов. У него нет обязательного сканера, баллов, установки зависимостей или сетевых вызовов.

В основе редакторские решения: сохранить полезную фразу; убрать мешающую оболочку; проверить, не изменилось ли утверждение. Содержательное противопоставление, термин и нужное тире допустимы. Авторскую манеру нельзя создавать выдуманными историями, эмоциями или намеренными ошибками.

## Использование

```text
$russian-editor Отредактируй сообщение. Сохрани сроки и прямой тон:
[текст]
```

```text
$russian-editor Проверь текст, не переписывай. Покажи конкретные проблемы:
[текст]
```

```text
$russian-editor Убери только повторения:
[текст]
```

```text
$russian-editor Напиши сообщение по этим тезисам:
[факты и желаемое действие адресата]
```

## Установка

Для проектной установки в агент, который обнаруживает `.agents/skills`, скопируйте **папку целиком** из этого репозитория:

```sh
mkdir -p /path/to/project/.agents/skills
cp -R skills/russian-editor /path/to/project/.agents/skills/
```

Путь `/path/to/project` замените путём своего проекта. Для других агентов используйте их каталог скиллов. Установка состоит в копировании Markdown и YAML; никакой код при этом не выполняется. При необходимости обновите список скиллов в своём агенте.

Подробные правила находятся в [SKILL.md](skills/russian-editor/SKILL.md), разборы решений в [examples.md](skills/russian-editor/references/examples.md).

## Проверка качества

В [eval/cases.json](eval/cases.json) есть 16 сценариев с условиями приёмки. Это ручной набор для проверки на выбранной модели, а не автоматический детектор или оценка человеческого авторства.

Процедура и границы проверки описаны в [eval/README.md](eval/README.md). Результаты текущего контрольного прогона находятся в [eval/results.md](eval/results.md). Проход этих сценариев не гарантирует сохранение смысла на любом тексте.

## Происхождение

Для сравнения изучен [ilyautov/humanizer-ru](https://github.com/ilyautov/humanizer-ru) и его инструкции редактуры, аудита и сверки, доступные 7 октября 2026 года. Этот проект не является форком и не содержит исходный каталог паттернов, сканер, тексты примеров или код того проекта. Инструкции и демонстрационные материалы написаны отдельно.

Предпочтения: небольшая правка, простой русский, точные рабочие статусы, авторские термины и отсутствие вводных фраз перед готовым сообщением. Публичные примеры вымышленные; личные адреса и внутренние рабочие переписки в пакет не включены.
